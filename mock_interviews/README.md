# Mock Interviews

Practise *out loud*, with a timer, closed notes. Use after each gate in [../ROADMAP.md](../ROADMAP.md#7-readiness-checks).

| File | Use |
|------|-----|
| [question_bank.md](question_bank.md) | Cross-module "bridge" questions for modules 00 to 14 with model answers (connected understanding) |
| [question_bank_15_to_21.md](question_bank_15_to_21.md) | Deep questions for modules 15 to 21, organised by module and by six types: Concept, Math (worked numbers), Implementation, Debugging, Architecture, Performance. Module 21 (inference engineering) has about 25 |
| [live_coding_drills.md](live_coding_drills.md) | Timed coding tasks: Python, DSA, agent loop, API (1-13), then ML/LLM/inference drills (14-23: backprop, BPE, online softmax, LoRA, int4 packing, KV bytes, prefix cache, chunker, CTC, token bucket) |
| [debugging_drills.md](debugging_drills.md) | Cold debugging practice: the `broken_*` files (1-13), then bugs injected into modules 15 to 21 (14-24) |
| [mock_scripts.md](mock_scripts.md) | Three full 45-minute mock interviews with timing, questions, follow-ups and scoring hooks: LLM inference engineer, RAG and document-intelligence engineer, ML engineer fundamentals |
| [scorecard.md](scorecard.md) | Self-scoring sheet by area plus a per-question tracker; track weak areas |

Protocol: 45 min = 5 min explain a past project/capstone, 20 min live coding, 10 min debugging drill, 10 min concept questions. Or run one of the scripts in [mock_scripts.md](mock_scripts.md) end to end. Record yourself once; listen for filler and unexplained jargon.

Suggested sequence: (1) read a module's `INTERVIEW_GIST.md`; (2) answer that module's questions in the bank aloud, covering the answers; (3) do one coding drill and one debugging drill from the module; (4) run a script when three modules are done; (5) score everything in the scorecard and re-test anything under 2.

Each module README also has its own interview Q&A. Modules 15 to 21 also have a cram sheet (`INTERVIEW_GIST.md`) in their folder.
